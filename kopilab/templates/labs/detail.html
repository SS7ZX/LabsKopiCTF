Setup Burp (cukup sekali)

Jalankan KopiLab, buka http://127.0.0.1:5000 lewat Proxy > Open browser, lalu pastikan Intercept is off. Detail setup awal ada di Deep Dive Burp Suite. Bagian di bawah ini bukan panduan umum: setiap langkah mengikuti request dan state khusus lab {{ lab['title'] }}.

Playbook Burp khusus lab ini

Request yang harus dicari: {{ lab['burp_guide']['request'] }}

Di browser Burp, lakukan aksi baseline yang disebut di bawah. Di Proxy > HTTP history, pilih request dengan method/path yang sama persis seperti target. Klik kanan → Send to Repeater. Jangan memilih request CSS, JavaScript, atau halaman navigasi lain.

  1. Bangun state dan baseline khusus lab. {{ lab['burp_guide']['baseline'] }} Kirim salinan request pertama di Repeater tanpa perubahan. Pastikan respons cocok dengan aksi browser sebelum menguji input.
  2. Catat bagian request yang diuji. Request lab ini: {{ lab['burp_guide']['request'] }}. Tandai parameter/header/ID yang disebut materi. Untuk POST, pastikan Content-Type dan posisi body sesuai request asli; pertahankan host, path, cookie sesi, dan semua nilai lain.
  3. Lakukan eksperimen lab, satu perubahan saja. {{ lab['burp_guide']['exercise'] }} Sebelum menekan Send, bandingkan request yang diedit dengan baseline: hanya field yang sedang diuji yang boleh berubah.
  4. Baca response untuk bukti yang disebut lab. {{ lab['burp_guide']['analysis'] }} Periksa response di Repeater, bukan hanya notifikasi browser. Catat status, header indikator, field JSON/HTML yang relevan, dan perubahan state. Respons sukses generik saja belum membuktikan dampak.
  5. Ulangi kontrol sah dan bandingkan Secure. {{ lab['burp_guide']['secure'] }} Ganti mode melalui UI, lalu tangkap request baru agar sesi/mode yang digunakan benar. Untuk alur bertahap, ulangi dari request pertama; jangan memakai state yang dibuat pada mode sebelumnya.
  6. Tutup eksperimen dengan bukti minimal. Gunakan daftar langkah lab dan bukti yang perlu dicatat di halaman ini. Jangan mengulang POST yang mengubah state kecuali langkah lab meminta; jangan masukkan nilai cookie/token ke catatan.

Kalau mentok: diagnosis langkah demi langkah

Kerjakan pemeriksaan ini berurutan. Setelah menemukan penyebabnya, ulangi hanya request yang diperlukan—jangan terus mengirim POST yang mengubah state.

  1. Request tidak muncul di HTTP history. Pastikan aksi dilakukan di browser yang dibuka lewat Burp Open browser, bukan browser biasa. Pastikan URL tetap http://127.0.0.1:5000, lalu lakukan lagi aksi spesifik lab pada bagian Langkah praktikum. Kembali ke Proxy > HTTP history, hapus teks filter pencarian jika ada, dan cari path {{ lab['endpoint'] }}. Untuk request form, tekan tombol submit pada halaman lab; sekadar membuka halaman belum tentu mengirim POST target.
  2. Request ada, tapi sepertinya bukan request lab. Cocokkan method dan path dengan {{ lab['burp_guide']['request'] }}. Klik request yang benar, cek query/body untuk field yang disebut petunjuk, dan pastikan bukan request CSS, JavaScript, /labs, atau /me. Untuk GET, nilai sering berada setelah tanda ?; untuk POST, pilih tab/body request dan cari field form. Jika field yang diuji tidak ada, kembali ke browser dan lakukan aksi yang benar sebelum mengirim ke Repeater.
  3. Repeater mendapat redirect login, 401, atau sesi tampak hilang. Login ulang di browser Burp dengan akun latihan yang diminta materi, lalu tangkap request target yang baru dan kirim request baru itu ke Repeater. Jangan menyalin cookie dari chat/screenshot atau mencampur request dari sesi browser yang berbeda. Pertahankan sesi browser latihan apa adanya.
  4. Respons 400 atau pesan format/body tidak valid. Bandingkan Content-Type dengan request baseline. Jangan mengubah form-urlencoded menjadi JSON, jangan memindah parameter query ke body, dan jangan mengetik ulang request multipart secara manual. Kembalikan body baseline, kirim untuk memastikan format valid, lalu ubah satu nilai saja. Biarkan Burp memperbarui panjang body.
  5. Respons 403/404 dan belum tahu apakah ini gagal atau hasil yang benar. Baca body JSON/HTML dan ikuti kontrak lab: penolakan pada Secure sering memang hasil yang diharapkan. Periksa apakah akun, ID fixture, dan urutan prasyarat sudah benar. Gunakan nilai milik sendiri sebagai kontrol; untuk pengujian akses, ubah hanya ID objek. Jangan menebak ID di luar fixture yang disebut materi.
  6. Request sukses, tetapi flag atau dampak yang diharapkan tidak terlihat. Jangan kirim ulang berkali-kali. Periksa response Repeater bagian header dan body, bukan hanya halaman browser. Flag hanya muncul jika kondisi lab terpenuhi. Cocokkan field bukti di checklist khusus lab ini; jika alur bertahap, pastikan setiap tahap sebelumnya berhasil dan memakai sesi yang sama. Contoh: buat quote/job/challenge dahulu sebelum confirm/download/complete.
  7. Vulnerable dan Secure terlihat sama. Pastikan mode berubah melalui tombol KopiLab di browser Burp, lalu tangkap request baru setelah perubahan. Untuk Secure, mulai ulang rangkaian stateful dari tahap pertama dengan sesi/mode yang sama. Jangan membandingkan request lama yang dibuat di mode lain atau state yang sudah terpakai.
  8. Masih belum ketemu setelah semua pemeriksaan. Baca catatan pemecahan masalah yang ditulis khusus untuk materi ini: {{ lesson['stuck'] or lab['burp_guide']['analysis'] }} Setelah itu buka petunjuk pertama pada bagian Petunjuk; lanjut satu tingkat setiap kali agar penyebabnya tetap bisa ditelusuri.
Aturan aman saat debug

Gunakan satu tab Repeater untuk menjaga urutan dan sesi, beri label request seperti baseline, uji, dan secure, lalu catat hanya nama field/status/hasil. Jangan catat nilai Cookie, token, password, atau data pribadi. Bila state sulit dipulihkan, gunakan reset yang disediakan KopiLab hanya setelah memastikan kamu tidak sedang memakai database bersama atau menyimpan progres yang ingin dipertahankan.

Catatan Repeater

Replay request dapat mengubah data atau memakai ulang aksi. Pertahankan host 127.0.0.1:5000, kirim satu perubahan terukur, dan baca response sebelum mengirim lagi. Jangan menyalin header Cookie ke catatan atau membagikannya.

Gunakan Burp hanya pada KopiLab lokal yang kamu jalankan sendiri. Jangan mengubah tujuan request ke situs, komputer, atau server lain.
