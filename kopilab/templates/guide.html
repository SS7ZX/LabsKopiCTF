1 · DARI KLIK KE HASIL

Bagaimana sebuah halaman dibuka?

Bayangkan browser seperti pelanggan yang mengirim pesanan ke dapur. Browser meminta alamat, Flask memilih fungsi yang menangani alamat itu, fungsi membaca atau mengubah data SQLite, lalu Jinja menyusun halaman HTML untuk dikirim kembali.

  1. Browser mengirim request. Contoh: membuka halaman depan atau mengirim form login.
  2. Flask mencocokkan URL. Route di dalam blueprint menentukan fungsi yang dijalankan.
  3. Fungsi memeriksa input dan sesi. Sesi menyimpan konteks browser seperti akun yang sedang masuk dan pilihan mode.
  4. Database membaca atau menyimpan data. Contohnya daftar produk, pesanan, atau progres lab.
  5. Template Jinja membuat tampilan. HTML memakai data yang diberikan route dan mewarisi kerangka `base.html`.
  6. Browser menerima respons. Respons bisa berupa halaman, JSON untuk API, redirect, atau file.
Coba sendiri: buka toko, lalu pencet halaman produk. Pada Request Inspector, perhatikan method, alamat, SQL terakhir, dan header respons. Setiap klik biasanya menghasilkan request baru.

Cara menelusuri satu fitur di source code

  4. Lihat `kopilab/templates/` untuk memahami bagaimana hasil route ditampilkan.
  5. Cari tes bernama mirip di `tests/` untuk melihat input uji dan hasil yang diharapkan.

Tombol “Reset progres saya” menghapus progres pemain ini saja. “Reset database lokal” mengembalikan data seed dan menghapus progres semua pemain dalam database lokal—pakai hanya jika memang ingin mulai ulang.

4 · VULNERABLE VS SECURE

Satu alamat, dua pelajaran

Pilihan mode ada di header dan disimpan dalam sesi browser. URL lab tidak berubah. Route yang sama membaca pilihan mode dan memilih perilaku latihan atau pemeriksaan aman.

Vulnerable

Perhatikan kesalahannya

Untuk lab, server sengaja melakukan satu hal yang salah agar dampaknya bisa diamati—misalnya memakai harga dari form browser.

Secure

Ulangi setelah diperbaiki

Handler yang sama memeriksa data dari sumber tepercaya. Contohnya mengambil harga katalog dari database, bukan mempercayai nilai kiriman browser.

Belajar yang disarankan: catat hasil Vulnerable, ganti mode, kirim request yang sama, lalu jelaskan perubahan apa yang membuat server menolak bug tersebut. Ini aplikasi belajar lokal, bukan contoh konfigurasi produksi siap pakai.

5 · SIMULASI TOKO

Alur belanja sebagai contoh aplikasi nyata

  1. Katalog dan pencarian: halaman depan mengambil daftar produk dari SQLite. Pencarian mengirim kata kunci melalui query string.
  2. Detail dan ulasan: route produk mengambil satu produk serta ulasan dan rating yang terkait.
  3. Keranjang: beberapa produk dan jumlahnya disimpan di sesi browser supaya mudah dibawa antarhalaman.
  4. Checkout keranjang: alur toko biasa menghitung ulang harga dari katalog server dan membuat order.
  5. Checkout lab lama: `/checkout` sengaja tetap ada agar flag lama dan pelajaran manipulasi harga tetap berfungsi.
  6. Akun dan akses: login, profil, transfer, riwayat, wishlist, dan panel admin punya route masing-masing.

6 · CARA BELAJAR DI TIAP LAB

Urutan yang membantu saat buntu

  1. Baca tujuan dan endpoint target. Cari tahu halaman atau request yang sedang diuji.
  2. Lakukan langkah praktikum lokal. Ubah satu nilai dalam satu waktu agar sebab dan hasilnya mudah terlihat.
  3. Bandingkan respons atau data. Gunakan Inspector bila perlu.
  4. Buka Petunjuk 1. Kalau masih buntu, lanjutkan Petunjuk 2 dan 3.
  5. Tidak apa-apa membuka solusi kapan saja. Baca jawaban, akar masalah, dan perbaikannya.
  6. Kirim flag untuk menyimpan progres; ulangi request dalam Secure dan jelaskan kenapa hasilnya berubah.

Flag adalah tanda bahwa kamu berhasil mencapai kondisi latihan. Flag bukan password atau data pengguna. Sebagian lab menampilkannya di respons halaman, JSON, atau header `X-Lab-Flag` sesuai contoh.

Progres dan laporan

Submit flag pada kartu lab atau di halaman detail. Server mencocokkan flag, lalu menulis satu baris ke lab_solves; constraint database mencegah satu lab terhitung dua kali untuk pemain yang sama. Halaman /scoreboard merangkum jumlahnya. Tautan laporan pada halaman lab membuat template Markdown berisi ringkasan, severity latihan, langkah reproduksi, dampak, dan rekomendasi.

7 · REQUEST INSPECTOR

Jendela untuk melihat “di balik layar”

Panel Inspector di bawah halaman menyimpan ringkasan request terakhir untuk pemain lokal yang sama.

  • Method dan path: jenis aksi HTTP (misalnya GET untuk membaca, POST untuk mengirim form) dan alamat yang diminta.
  • SQL terakhir: query yang secara eksplisit dicatat oleh route latihan. Pada Secure, nilai input terikat sebagai parameter, bukan ditempel ke sintaks SQL.
  • Header respons: metadata server/browser seperti Content-Type, status, dan cookie. Header dapat berubah berdasarkan mode.

Batasan penting: ini inspector pembelajaran, bukan pencatat semua operasi database. Ia menampilkan query yang dicatat route tertentu; request tanpa query tercatat menampilkan pesan bahwa tidak ada SQL pada request itu.

Urutan melihat data juga penting: panel di respons halaman membaca catatan request sebelumnya, sebab catatan request yang sedang berlangsung baru disimpan saat respons akan dikirim.

8 · PANDUAN BURP SUITE UNTUK PEMULA

Melihat request KopiLab lewat Burp Suite

Bagian ini untuk orang yang baru pertama kali memakai Burp Suite. Kamu tidak perlu punya pengalaman keamanan web. Ikuti langkahnya dari atas ke bawah. Tujuannya adalah melihat komunikasi antara browser dan KopiLab yang berjalan di komputermu sendiri.

Batas latihan: gunakan Burp hanya pada KopiLab lokal yang kamu jalankan sendiri. Alamat latihan adalah http://127.0.0.1:5000. Jangan mengganti tujuan ke situs publik, komputer orang lain, jaringan sekolah atau kantor, maupun server lain. Jangan membuka port KopiLab ke internet.

Sebelum mulai: kenali tiga jendela

Saat latihan, biasanya ada tiga jendela yang perlu dibedakan. Yang penting adalah tahu jendela mana yang menjalankan aplikasi dan jendela mana yang menampilkan lalu lintas.

  1. Terminal. Jendela ini menjalankan KopiLab. Biarkan tetap terbuka selama latihan. Jika terminal ditutup atau server dihentikan, halaman KopiLab tidak bisa dibuka.
  2. Browser Burp. Ini browser yang dibuka dari Burp dengan tombol Open browser. Gunakan browser ini untuk membuka KopiLab agar permintaannya melewati Burp.
  3. Burp Suite. Ini jendela untuk melihat daftar request di HTTP history, dan bila diperlukan menahan request di Intercept.

Request adalah permintaan browser kepada aplikasi, misalnya “tampilkan katalog” atau “cari kata kopi”. Response adalah jawaban aplikasi, misalnya halaman katalog atau hasil pencarian. Proxy adalah perantara. Dalam latihan ini, browser Burp mengirim request melalui Burp, lalu Burp meneruskannya ke KopiLab.

Angka di alamat juga penting. 127.0.0.1 berarti komputer yang sedang kamu gunakan. 5000 adalah port KopiLab. Burp biasanya memiliki listener lokal di port 8080. Port Burp dan port KopiLab punya tugas berbeda. Kamu tidak perlu mengubah keduanya untuk cara yang dijelaskan di sini.

Langkah 1: jalankan KopiLab

Kalau KopiLab belum pernah dijalankan di komputer ini, siapkan dependensinya dahulu. Buka PowerShell atau Command Prompt di Windows, lalu ketik perintah berikut satu demi satu. Tekan Enter setelah setiap baris.

cd C:\kopilab
py -3 -m venv .venv
.venv\Scripts\activate
python -m pip install -r requirements.txt
  • cd C:\kopilab berpindah ke folder proyek. Jika folder proyekmu berada di lokasi lain, ganti alamat folder ini dengan lokasi yang benar.
  • py -3 -m venv .venv membuat lingkungan Python proyek. Langkah ini biasanya hanya perlu dilakukan satu kali untuk setiap salinan proyek.
  • .venv\Scripts\activate mengaktifkan lingkungan tersebut di terminal yang sedang dipakai.
  • python -m pip install -r requirements.txt memasang paket yang diperlukan KopiLab. Komputer perlu akses internet saat paket belum tersedia dan perlu diunduh.

Untuk penggunaan berikutnya, buka terminal baru dan jalankan perintah berikut. Jangan jalankan setup pembuatan .venv berulang kali.

cd C:\kopilab
.venv\Scripts\activate
python run.py

Biarkan terminal berjalan. Tunggu sampai muncul alamat KopiLab, yaitu http://127.0.0.1:5000. Buka alamat itu di browser biasa untuk memastikan aplikasi dapat dimuat. Setelah berhasil, kamu boleh menutup tab browser biasa tersebut. Jangan tutup terminalnya.

Tanda berhasil: terminal tidak kembali ke prompt dan menampilkan bahwa server berjalan di alamat lokal. Jika terminal menampilkan traceback atau pesan error, berhenti dulu dan periksa pesan tersebut. Burp tidak dapat memperbaiki KopiLab yang belum berhasil dijalankan.

Langkah 2: buka Burp dan browser yang benar

  1. Buka aplikasi Burp Suite dari menu Start.
  2. Jika muncul pilihan cara memulai proyek, pilih pilihan sementara atau default, lalu lanjutkan sampai jendela utama Burp terbuka. Nama tombol bisa sedikit berbeda antarversi.
  3. Pilih tab Proxy.
  4. Cari dan klik Open browser. Burp akan membuka browser khusus yang sudah disiapkan untuk terhubung melalui proxy lokal Burp.
  5. Tunggu browser baru terbuka. Jangan gunakan browser biasa untuk langkah ini.
  6. Klik bilah alamat browser Burp, ketik http://127.0.0.1:5000, lalu tekan Enter.
  7. Pastikan halaman KopiLab tampil. Alamat harus memakai http://, bukan https://.

Untuk KopiLab lokal, sertifikat CA Burp tidak perlu dipasang. Jangan mengubah alamat bind aplikasi menjadi 0.0.0.0, jangan meneruskan port melalui router, dan jangan mengubah pengaturan agar komputer lain dapat mengakses server.

Langkah 3: lihat request pertama di HTTP history

Mulailah dengan melihat riwayat, bukan menahan request. Pastikan Intercept is off. Saat Intercept mati, browser bisa menggunakan aplikasi seperti biasa dan Burp tetap dapat mencatat request.

  1. Di browser Burp, tekan Ctrl+R untuk memuat ulang halaman KopiLab.
  2. Klik tautan Labs di navigasi KopiLab. Tunggu sampai halaman lab terbuka.
  3. Kembali ke jendela Burp Suite. Buka Proxy, lalu HTTP history.
  4. Lihat daftar yang muncul. Cari request dengan host 127.0.0.1 dan port 5000. Baris paling baru bisa berada di atas atau di bawah, tergantung pengurutan di versi Burp yang kamu gunakan.
  5. Klik satu baris request. Panel detail menampilkan isi request dan response. Jika panelnya kecil atau tidak tampak, coba pilih baris lain atau perbesar jendela Burp.
  6. Kembali ke browser Burp, klik halaman lain, lalu lihat HTTP history lagi. Kamu akan melihat request tambahan yang dihasilkan oleh navigasi tersebut.

Nama atau posisi panel Burp bisa berubah antarversi. Yang perlu dicari adalah tab Proxy, daftar HTTP history, dan detail untuk baris yang dipilih. Jangan khawatir jika tampilannya tidak persis sama dengan gambar atau panduan dari versi lain.

Langkah 4: pahami isi satu baris request

Pilih request halaman awal KopiLab atau halaman Labs yang baru kamu buka. Amati bagian-bagian ini tanpa mengubahnya:

  • Method. Jenis permintaan. GET umumnya dipakai untuk meminta halaman atau data. POST umumnya dipakai saat browser mengirim isi form.
  • URL atau path. Alamat yang diminta. Misalnya / berarti halaman depan, sedangkan /labs berarti katalog lab.
  • Headers. Informasi tambahan tentang request atau response, seperti jenis konten yang diterima browser. Header Cookie dapat berisi pengenal sesi, jadi jangan menyalin atau membagikannya.
  • Parameters. Nilai yang dikirim bersama request. Nilai dapat berasal dari alamat halaman atau dari form yang kamu isi. Request untuk halaman biasa mungkin tidak memiliki parameter.
  • Status response. Kode yang menunjukkan hasil pemrosesan. Contohnya, 200 biasanya menandakan aplikasi mengembalikan response, dan 302 biasanya menunjukkan browser diminta pindah ke alamat lain.
  • Response body. Isi jawaban aplikasi. Untuk halaman toko, isinya sering berupa HTML yang kemudian ditampilkan browser.
Latihan pengamatan pertama: pilih satu request GET ke /labs. Catat method dan path-nya. Lalu klik satu lab di browser, pilih request baru yang muncul, dan bandingkan path-nya. Untuk latihan pertama ini, cukup amati. Tidak perlu mengubah data atau mengirim request ke alamat lain.

Langkah 5: amati request dari form pencarian

Form pencarian adalah contoh sederhana untuk melihat perbedaan antara membuka halaman dan mengirim data. Gunakan hanya pencarian katalog KopiLab.

  1. Pastikan Intercept is off agar halaman tidak tertahan.
  2. Di browser Burp, gunakan kotak pencarian katalog KopiLab. Masukkan kata biasa, misalnya kopi, lalu tekan tombol Cari.
  3. Kembali ke Burp dan buka Proxy > HTTP history.
  4. Pilih request terbaru yang menuju ke host 127.0.0.1:5000.
  5. Perhatikan method, path, dan bagian parameter. Kata yang kamu cari mungkin terlihat sebagai parameter di URL atau di isi request, bergantung pada cara form mengirim data.
  6. Kembali ke browser dan lihat hasil pencarian. Hubungkan tindakan di browser dengan request yang kamu pilih dan response yang diterima.

Jangan mencoba nilai yang menargetkan layanan lain. Tujuan latihan ini adalah mengenali bagaimana input dari form tampak di request milik KopiLab lokal.

Langkah 6: gunakan Intercept bila instruksi lab memintanya

HTTP history hanya mencatat lalu lintas yang sudah lewat. Intercept berbeda: fitur ini menahan request sementara supaya kamu dapat melihatnya sebelum diteruskan ke KopiLab. Langkah ini opsional. Jika kamu hanya ingin belajar melihat request, HTTP history sudah cukup.

  1. Di Burp, buka Proxy > Intercept.
  2. Periksa tombol statusnya. Jika tertulis Intercept is off, klik satu kali untuk menyalakannya. Status harus berubah menjadi Intercept is on.
  3. Kembali ke browser Burp dan lakukan satu aksi sederhana di KopiLab, misalnya memuat ulang halaman awal.
  4. Kembali ke Burp. Jika request cocok dengan aturan intersepsi, Burp akan menampilkannya dan browser akan menunggu. Menunggu pada tahap ini adalah hal yang normal.
  5. Klik Forward untuk meneruskan request ke KopiLab. Jika ada lebih dari satu request tertahan, lanjutkan satu per satu sampai browser selesai memuat halaman.
  6. Gunakan Drop hanya jika ingin membatalkan request latihan yang sedang ditahan. Jika request di-drop, aplikasi tidak menerima request itu dan halaman mungkin tidak terbuka dengan normal.
  7. Setelah selesai, klik status Intercept agar kembali menjadi Intercept is off. Periksa statusnya sebelum melanjutkan memakai aplikasi.
Browser terlihat macet? Jangan langsung menutup aplikasi. Kembali ke tab Intercept. Jika ada request yang menunggu, klik Forward untuk meneruskannya. Setelah halaman pulih, matikan Intercept. Request yang tertahan memang membuat browser menunggu.

HTTP history dan Intercept, bedanya apa?

Kalau ingin memakai browser biasa

Cara paling mudah adalah tetap memakai tombol Open browser di Burp. Browser biasa tidak otomatis mengirim lalu lintas melalui Burp. Browser tersebut perlu dikonfigurasi agar memakai proxy lokal Burp, dan pengaturannya berbeda menurut browser maupun sistem operasi.

Jika kamu sudah memahami pengaturan proxy, periksa listener Burp pada pengaturan Proxy. Listener standar umumnya berada di 127.0.0.1:8080, tetapi gunakan nilai yang benar-benar ditampilkan di Burp. Pastikan browser tidak mengecualikan alamat loopback 127.0.0.1 dari proxy. Jangan mengubah listener supaya dapat menerima koneksi dari komputer lain. Jika tidak yakin, tutup browser biasa dan gunakan Open browser.

Akhiri latihan dengan rapi

  1. Pastikan status Intercept kembali menjadi Intercept is off.
  2. Tutup browser Burp jika sudah selesai.
  3. Kembali ke terminal yang menjalankan KopiLab, lalu tekan Ctrl+C untuk menghentikan server.
  4. Tutup Burp Suite jika tidak akan digunakan lagi.

Kamu tidak perlu menghapus database untuk mengakhiri sesi. Burp juga tidak perlu dibiarkan aktif setelah latihan. Jika hanya ingin melihat ringkasan request terakhir saat menggunakan KopiLab, kamu bisa memakai Request Inspector bawaan.

9 · BATAS LAB

Kenapa simulator harus tetap lokal?

CSRF simulator berjalan di port 9000 dan service SSRF latihan di port 5001. Keduanya bind hanya ke `127.0.0.1`; SSRF dibatasi ke service internal KopiLab. Upload disimpan di folder proyek dan tidak pernah dijalankan. Simulator tidak membaca cookie, tidak menebak password, dan tidak menghubungi situs pihak lain.

Untuk mencoba simulator CSRF, buka terminal kedua lalu jalankan python run_attacker.py; halaman tetap hanya ditujukan ke `127.0.0.1:5000`. Service SSRF port 5001 mulai bersama aplikasi utama dari `run.py`.

Aturan kelas: lakukan request hanya ke KopiLab di komputer sendiri. Jangan ganti tujuan ke alamat internet, komputer teman, alamat kantor/kampus, atau server publik. Hentikan server dengan Ctrl+C setelah kelas.

11 · CARA MEMASTIKAN SISTEM

Apa yang diperiksa oleh tes otomatis?

  • Tes mode Vulnerable memastikan perilaku lab lama dan tambahan masih bisa diamati pada data lokal.
  • Tes Secure memastikan input serupa ditolak atau diproses dengan aturan lebih aman.
  • Tes toko memeriksa katalog, detail produk, keranjang, checkout, wishlist, dan halaman akun.
  • Tes belajar memeriksa semua halaman materi, hints, solusi, submit flag, scoreboard, reset, Inspector, dan laporan.
Menjalankan tes di Windows:
.venv\Scripts\activate
python -m pytest -q
Tes memakai database sementara. Database toko lokalmu tidak dipakai oleh tes.

Ringkasnya: browser mengirim request → Flask memilih route → handler menjalankan aturan mode → SQLite menyimpan atau membaca data → Jinja menyusun respons. Saat memahami satu route, ikuti urutan ini dan kamu bisa menelusuri hampir semua fitur KopiLab.
